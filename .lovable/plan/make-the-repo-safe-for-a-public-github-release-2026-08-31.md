# Make the repo safe for a public GitHub release

Goal: anyone can clone the repo, plug in their own backend, and run the site — with none of your private details left in the code.

Note on your live site: as you chose full placeholders, the published site will show "Your Brand" and placeholder contact info until you set the brand env values in the project's environment (a short "restore my details" section will be in the README).

## About the backend ("is Supabase online?")

Yes — the database, auth, storage and order data live in a hosted cloud (Supabase) project tied to this app. That project is *not* in the repo; only the SQL migrations are. Nobody who clones the repo can reach your data, because:

- the backend URL + key are removed from the repo,
- every table has row-level security, so even with the public key a stranger only sees products, never orders,
- admin rights come from an email allowlist row inside your database.

Anyone cloning must create their own free Supabase project and apply the included migrations. The README covers this step by step.

## Technical notes

- `.env` is generated by the platform and stays on disk; it just stops being tracked via `.gitignore`, and `.env.example` documents the variables.
- Brand config keeps working when env vars are absent by falling back to placeholders, so a fresh clone runs with zero config.
- No database, RLS, or business-logic changes — this is sanitising + documentation only.
- Build verified with `bun run build` at the end.
